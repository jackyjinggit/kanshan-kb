# 归因模块 · 使用说明与交接包（2026-09-12）

> 定位：任务板「归因模块（最重 · 9/15 现场演示一条真实归因）」的**起手货**——在上面改还是推倒重写都随你，规则/口径/失效条件已按任务板规格 v1 落地。
> 接口口径：输入=一组数据点（时间/发了什么/涨跌/互动数）→ 输出=归因卡（一句话原因 + 可信度高/中/低 + 一个下一步动作建议）。

## 一、30 秒跑通

```bash
# 方式①：直接用真实账号聚合样例（本机 data/real 有数据时）
python scripts/attribution.py --demo --out out/attribution_demo.json

# 方式②：喂自己的数据点（50 条公开脱敏样例在 examples/）
python scripts/attribution.py --in examples/attribution_points_50_public.jsonl --out out/my.json
```

实测（本人账号 809 条创作聚合出最近 50 天）：**50 张归因卡，高/中/低 = 10/16/24**。

## 二、输入格式（日粒度数据点 jsonl，每行一天）

```json
{"date": "2026-07-26", "action": "publish", "title": "…", "delta_likes": 10, "comments": 8}
```

- `action`：`publish`（发文）/ `hotlist`（上热榜）/ `none`（无动作），可扩展
- `delta_likes`：当日互动增量（可负）
- `comments`：当日评论数（辅助信号）

`--from-real`：输入是 `scripts/zhihu_fetch.py` 抓的全量创作 jsonl 时，自动按发布日聚合成上述数据点。

## 三、判断规则（v1 = 任务板原文口径）

| 情形 | 归因 | 可信度 |
|---|---|---|
| 涨 + 当天有动作（发文/热榜），且评论同步活跃 | 归因到该动作，信号可信 | **高** |
| 涨 + 当天有动作，但互动单薄 | 动作为主因 + 自然波动叠加 | 中 |
| 跌/平 + 当天有动作 | 「动作负效应待验证」——**不硬编「内容不行」** | 低 |
| 当天无动作 | 「外部因素/波动，不硬编原因」 | 低（标不知道） |

产品价值观（写进演示话术）：**宁可标「不知道」，不硬编原因；每张卡带失效条件。**

## 四、口径诚实声明（答辩防身）

- `--from-real` 的 delta_likes 是**事后口径**（该日条目当前赞合计/差分），非实时日增量；实时口径需 sampler 快照差分（赛期数据积累后自动升级）。输出体 `note` 字段已自带声明。
- 阈值（涨跌 10 / 评论中位数地板）是启发式初值，`falsify` 字段写明「用你账号后续表现复核后应再校准」。

## 五、交接清单（本包五件）

| 件 | 位置 | 说明 |
|---|---|---|
| 归因引擎 | `scripts/attribution.py` | 纯 stdlib，零依赖，直接跑 |
| 真实聚合完整版（含标题，**本机私有**） | `data/attribution_points_50_full.jsonl`（注意：勿放进 data/real/，网关会把 .jsonl 当账号文件加载） | 50 天数据点含真实标题，不入库 |
| 公开脱敏样例 | `examples/attribution_points_50_public.jsonl` | 同数据去标题/URL，可公开 |
| 演示输出样张 | `out/attribution_demo.json`（本地跑一次即得） | 50 卡 + 高/中/低分布 |
| 日内归因（补充） | `scripts/cards.py` 的 `day_card()` | 24h 曲线节点归因，现场演示可与本模块串联 |

## 六、建议改法（下一棒的三个抓手）

1. **接入日内粒度**：`scripts/sampler.py` 每 5 分钟快照已在攒数，赛期几天数据足够把「日粒度」升到「小时级归因」（`cards.day_card` 已有节点窗口逻辑可复用）。
2. **动作清单扩展**：action 目前只有 publish/hotlist/none——把「互动引导」「置顶评论」「修改回答」等动作补进数据点，归因会立刻变细。
3. **LLM 归因文案**：规则版给的是结构化 cause；接一个便宜快速模型把 cause 润成自然语言（注意带上 confidence 与 falsify，别让模型把「不知道」润成「知道」）。
