## 方法定义与边界

以明确用途、账号隔离和最小字段集管理采集。浏览器登录、Access Secret 与 OAuth 用户授权是不同状态，不能互相替代。公开内容也不能推定为可任意训练、镜像或公开再分发；本知识库保存原创摘要和来源链接，不保存私人账号历史。

## 数据前置与诊断

需要字段—用途表、来源与授权范围、账号隔离标识、保存期限及接口成功/失败状态。M10 的诊断优先为“采集权限或身份关联异常”；鉴权失败不是空数据，未知值也不是零。仅检查凭证是否配置和调用状态，不要求模型读取密钥原文。

## 处方：最多三个动作

1. 按当前用途列最小字段：例如作品标识、日期、赞评藏及来源；不为做趋势额外抓取完整关注关系或私信。基于同意的处理说明目的、字段、期限与撤回方式；变更用途时重新核对处理依据。导入私人数据前确定访问范围和清理条件。
2. App Key、Access Secret 与 OAuth Token 放系统安全凭证存储或受控后端环境，不进源码、普通配置文件、浏览器存储、前端响应和日志。App ID 是应用标识，不应与密钥混淆。后端处理授权码交换，严格核对登记的回调地址，并执行下列短期授权码防护；会话用一次性随机 state 关联，并实测平台是否回传。回调缺失 state、与会话不匹配、过期或重放时停止；平台不回传且没有经验证的替代 CSRF 防护时，不通过接入验收。PKCE 支持必须另行验证，不能假设知乎已经实现。
3. Token 失效、缺授权或账号不匹配时停止该账号采集，不回退到开发者自己的数据。按用途到期、撤回与删除请求清理适用记录和会话；发现泄漏先撤销或轮换相应凭证，再检查访问范围，不把旧密钥复制到问题报告。

### 动作 2 的短期授权码防护

官方协议通过回调 URL 的 `authorization_code` 传码，接收端可兼容 `code`。这是正常协议交付，不能禁止回调 URL 携带码；应用应只在后端短暂读取、交换并结束该次授权流程，不让前端脚本或页面正文再次读取和展示。

反向代理、应用、错误采集和分析系统应在写入前排除授权码、state 及含这些参数的完整回调 URL；只记录脱敏的流程状态，不把原请求地址附进异常或截图。回调响应不加载第三方脚本、图片或外链资源，设置适当的 `Referrer-Policy`（本项目采用 `no-referrer`）及禁止缓存的响应策略。完成或失败后跳转到不含授权码与 state 的干净地址，再展示结果或加载正常页面资源；跳转不能作为已清除浏览历史的证明。

同一会话完成后拒绝重复回调，避免重复交换。授权服务端是否拒绝已使用或过期的码仍须实测，不能把本地拦截等同于服务端一次性使用已经验收；授权码不为防重而以明文写入普通日志或永久记录。

## 复盘与可证伪条件

本地来源卡：[OAuth 安全最佳实践](../知识库/全球研究资料/GR-C01_OAuth安全最佳实践.md)、[最小范围与用户控制](../知识库/全球研究资料/GR-C02_个人信息最小范围与用户控制.md)。

用两个获授权测试账号检查隔离；使用过期凭证验证明确失败且无另一账号数据返回；检查构建产物与日志不含测试密钥；走一遍撤回和适用数据删除流程。回调防护先用明确合成、无授权能力的测试码覆盖成功和错误分支：确认代理/应用/错误日志没有码、state 或完整回调 URL，回调没有第三方资源请求，响应策略生效，后续页面地址干净，重复回调被拒绝。只保存脱敏的测试结果，不为验收复制真实码。合成码测试不能代替真实授权服务端的过期与重复兑换验收，尚未联调时应标待测。任一实际检查失败则该项不通过；上述检查是待执行验收，文档写成不代表已完成。

## 常见错误

用 OAuth 失败冒充空账号；把 App ID 与私钥一并禁止正常授权跳转；在前端拼装 Access Secret；把用户输入的数据直接发往未说明的境外服务；将“永久保存更方便”当作保存理由。
