# 看山 · 本地演示（两条入口）

一个页面、一个进程、零依赖：`python demo/server.py` → 浏览器打开 `http://127.0.0.1:8699/`。
也可以双击 `demo/run_demo.bat`（Windows）。

## 两条入口（对应现场演示的两个场景）

| 入口 | 接口 | 需不需要账号授权 | 输出 |
|---|---|---|---|
| ① 账号诊断 | `POST /api/diagnose` | 演示用的是**合成数据**（真实数据走本人授权抓取） | 七节诊断报告 + 15 条处方（异常信号 → M1~M10 模块 → 具体动作 → 依据 md → 失效条件） |
| ② 贴入式内容分析 | `POST /api/analyze` | **不需要**。贴一段文本就能出分析 | M4 爆款要素体检（4 维度打分）+ 结构诊断 + M10 合规风险自查 + 校验规则插槽 + 失效条件 |

入口二是为「评委现场没有账号授权」准备的：把一段内容贴进文本框即可看到完整分析链路。

## 为什么另起一个 demo/ 而不是改既有的前端目录

工作区外另有一个前端原型目录（石同学的，含本地凭证与真实账号检索结果）。**本目录完全自包含**，不复制它的任何代码、不读它的凭证文件：
- 它不进公开仓库 → 不会把凭证风险与真实账号信息带进公开库；
- 演示不依赖它的运行环境，离线即可跑；
- 若后续要把它接上同一套引擎，只需两个接口：`/api/diagnose` 与 `/api/analyze`（见仓库内对接说明）。

## 接口速查

```
GET  /api/status              引擎状态、规则插槽来源、演示账号类型、免责声明
GET  /api/health              探活
POST /api/diagnose            {user, archetype, days, n} → 诊断 + 信号 + 处方
POST /api/analyze             {title, text} → 内容分析
```

`archetype` 取 `polluted`（被历史爆款污染的老号）/ `newbie`（新手号）/ `vertical`（垂类号）/ `omnivore`（多题材号）。
非法值直接 400，不会被当成路径或文件名。

## 已知边界（演示时请一并说明）

- 演示数据是 `scripts/demo_synth.py` **合成的示例数据**，不是任何真实账号数据；页面与报告里均有标注。
- 平台不提供的量（粉丝数 / 曝光量 / 小时级点击率 / 完播）本工具**不推断、不填数**；缺失处写「样本不足」。
- 近期窗口样本 < 8 条时，引擎**自动回退到全量基线**并在报告里声明（页面会弹出提示）——此时节奏/稳定性类结论不可采信。
- M10 合规项是**自查提示**，依据公开平台规范整理，不构成平台判定。
- 正文超过 2 万字时只分析前 2 万字，并在报告中标注。
- 数据锚点取**数据内最新一条**，不是墙钟时间 → 同一份数据任何时候跑，结论一致（可复现）。
