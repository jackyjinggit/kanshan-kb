# 看山 · 本地演示（两条入口）

一个页面、一个进程、零依赖：`python demo/server.py` → 浏览器打开 `http://127.0.0.1:8699/`。
也可以双击 `demo/run_demo.bat`（Windows）。

**跑真数据（本人账号）**：

```
python scripts/zhihu_fetch.py --out data/real/contents_<账号标签>_<日期>.jsonl   # 需先 zhihu-cli auth set
python demo/server.py                                                          # data/real/ 下有几个文件就加载几个账号
```

**换账号 = 多放一个文件**：`data/real/*.jsonl` 里每个文件算一个账号，网关启动时**全部加载**，
页面账号按钮里各占一个（默认选中最近拉取的那份）；**不用改代码、不用重启**（重拉同一文件后刷新即生效）。
也可以显式指定，`--data` 的先后顺序就是按钮顺序：

```
python demo/server.py --data data/real/contents_甲_20260910.jsonl --data-user 甲 \
                      --data data/real/contents_乙_20260910.jsonl --data-user 乙
```

换第二个账号拉数的两条路（`zhihu-cli` 自己只有一份凭证：`auth set` / `logout` / `status`，**没有多 profile**）：

| 路径 | 命令 | 影响范围 |
|---|---|---|
| 临时（推荐，不动凭证库） | `$env:ZHIHU_ACCESS_SECRET="<第二个账号的 secret>"` 后跑 `zhihu_fetch.py` | 只对当前 shell 生效，关掉即回到原账号 |
| 换库 | `zhihu-cli auth set "<第二个账号的 secret>"` | 改本机凭证库的当前账号（原账号需再 set 回来） |

CLI 原话（`zhihu-cli auth --help`）：「环境变量 `ZHIHU_ACCESS_SECRET` 优先于系统凭证库。CLI 不读取 `.env`，
也不提供明文文件降级存储。」——**本工具不读、不写、不打印任何 secret**，上面两条都由操作者自己在 shell 里执行。

⚠️ **账号名只能由人给**：`zhihu-cli` 不返回账号身份（`auth status` 只有掩码 `c6f5...ec63`，`capabilities`
只有命令表），所以账号标签来自 `--data-user`（或 `文件名=<名>` 映射），没有就退回文件名推导、再退到「本人账号」。
**目录扫描时不做位置配对**（免得把名字贴到错的账号上）——要精确命名就用 `--data` 显式列。

真实数据模式与合成模式**用的是同一套引擎**（`signals.py` → `prescribe.py` → `zhihu_diagnose.py`），
只有取数来源不同；页面顶部会打「真实数据 · N 个账号」标记，账号清单里带「合成·」前缀的是**对照账号**（脚本生成，非真实账号）。

## 两条入口（对应现场演示的两个场景）

| 入口 | 接口 | 需不需要账号授权 | 输出 |
|---|---|---|---|
| ① 账号诊断 | `POST /api/diagnose` | 合成模式不用；真实模式走**本人 zhihu-cli 授权**（`--data`） | 七节诊断报告 + 15 条规则族结论（按状态分四组），每条含 异常信号 → M1~M10 模块 → 具体动作 → 依据 md → 失效条件 |
| ② 贴入式内容分析 | `POST /api/analyze` | **不需要**。贴一段文本就能出分析 | M4 爆款要素体检（4 维度打分）+ 结构诊断 + M10 合规风险自查 + 校验规则插槽 + 失效条件 |

入口二是为「评委现场没有账号授权」准备的：把一段内容贴进文本框即可看到完整分析链路。

## 处方为什么要分组：换一个账号，建议就该不一样

15 条规则族**每次都全跑**（规则族是覆盖清单，避免漏检），但只有真正命中的才进「行动清单」：

| 状态 | 含义 | 页面呈现 |
|---|---|---|
| `alert` | 命中异常信号 → 本期就动 | 完整卡片（信号 / 模块 / 动作 / 依据 / 失效条件） |
| `watch` | 弱信号，够不上异常但值得盯 | 压缩一行 |
| `unknown` | 样本不足，测不出来 | 只给「先补什么样本」，不给结论 |
| `ok` | 该维度不是当前瓶颈 | 折叠成一句结论，明确劝你别在这里花时间 |
| `error` | 规则执行异常 | 单列并标「属缺陷信号，不是数据结论」 |

「各自不同」是**机器可查**的，不是文案修辞：
- `scripts/e2e_test.py` 有一条闸门「换账号各自出不同建议」——三个不同账号必须给出三套不同的行动清单集合，条数也不许恒定；
- `tests/test_prescribe.py` 有 8 个账号的逐条状态合法性 + 分组完备性 + 源码静态闸门（**每个规则分支必须显式声明状态**，漏标即失败）。

实测：4 个演示原型 → 行动清单 5 / 6 / 7 / 9 条，互不相同；同原型只换用户名也不同。真实 48 条样本 → 行动 8 / 观察 1 / 待补样本 1 / 已排除 5。
真实 809 条（本人账号，zhihu-cli 拉取）→ 近 30 天 行动 9 / 观察 1 / 待补 1 / 已排除 4；近 60、90 天 行动 10 / 观察 1 / 待补 1 / 已排除 3
——**窗口一换，清单也跟着变**，所以「不同账号不同建议」在真实数据上同样成立。

## 为什么另起一个 demo/ 而不是改既有的前端目录

工作区外另有一个前端原型目录（石同学的，含本地凭证与真实账号检索结果）。**本目录完全自包含**，不复制它的任何代码、不读它的凭证文件：
- 它不进公开仓库 → 不会把凭证风险与真实账号信息带进公开库；
- 演示不依赖它的运行环境，离线即可跑；
- 若后续要把它接上同一套引擎，只需两个接口：`/api/diagnose` 与 `/api/analyze`（见仓库内对接说明）。

## 接口速查

```
GET  /api/status              引擎状态、规则插槽来源、账号清单、**数据来源（合成/真实）**、免责声明
GET  /api/health              探活
POST /api/diagnose            {user, archetype, days, n} → 诊断 + 信号 + 处方
POST /api/analyze             {title, text} → 内容分析
OPTIONS *                     预检（只对 Origin: null 放行）
```

启动参数：`--host`（只能本机）/ `--port`（默认 8699）/ `--no-browser` / `--data <真实 jsonl>` / `--data-user <显示名>`。

`archetype` 取 `polluted`（被历史爆款污染的老号）/ `newbie`（新手号）/ `vertical`（垂类号）/ `omnivore`（多题材号）；
真实数据模式下另有 `real`（本人真实账号，默认选中）。非法值直接 400，不会被当成路径或文件名。

**跨源只开一扇窗**：页面用 `file://` 直接打开、或落在沙箱预览面板里（Origin 为 `null`）时，会自动指向
`http://127.0.0.1:8699`，服务端也只对 `Origin: null` 回 CORS 头——**外站拿不到任何本地数据**（有闸门验这条）。

**页面为什么不用原生 `<select>`**：实机踩过一次——原生下拉在部分渲染器里会被下方按钮盖住，弹出层又是白底白字。
账号与窗口一律用可点按钮（chip），不赌渲染器。`scripts/e2e_test.py` 有一条闸门：页面里再出现 `<select` 即失败。

## 已知边界（演示时请一并说明）

- 演示数据是 `scripts/demo_synth.py` **合成的示例数据**，不是任何真实账号数据；页面与报告里均有标注。
- **真实数据模式**：`--data` 指定的 jsonl 只在本机读取、**不入库**（`data/` 与 `*.jsonl` 都在 `.gitignore` 内，红线扫描也跳过 `data/`）；
  页面与报告里标注真实条数与数据内最新日期；换一台机器要自己重新拉数（真实数据不随仓库走）。
- 知乎开放接口按页返回（`Limit ≤ 50`），全量需翻页；接口自报 `Paging.Totals` 与实际可拉条数可能差几条（已删/仅自己可见等），
  以**实际写入 jsonl 的条数**为准。
- 平台不提供的量（粉丝数 / 曝光量 / 小时级点击率 / 完播）本工具**不推断、不填数**；缺失处写「样本不足」。
- 近期窗口样本 < 8 条时，引擎**自动回退到全量基线**并在报告里声明（页面会弹出提示）——此时节奏/稳定性类结论不可采信。
- M10 合规项是**自查提示**，依据公开平台规范整理，不构成平台判定。
- 正文超过 2 万字时只分析前 2 万字，并在报告中标注。
- 数据锚点取**数据内最新一条**，不是墙钟时间 → 同一份数据任何时候跑，结论一致（可复现）。
