# 看山 · 创作校准引擎（Kanshan KB）

> 一句话：**把创作者的公开数据变成可执行的诊断与处方**——不是又一个数据看板，而是「哪里出了问题 → 为什么 → 下一步干什么」。

面向知乎创作者，纯本地可跑、0 API 成本（仅用开放平台免费额度），输出**可证伪**的结论。

---

## 一、它解决什么问题

创作者常见的三种自欺：

1. **看总量不看效率**：发了 400 条，均赞 3——越勤奋越亏
2. **凭感觉归因**："我内容不行" / "平台限流" / "题材冷门"——都不可证伪
3. **没有对照**：全量均赞被历史爆款拉高，看不出近期真实水平

看山的做法：**同期对照 + 分组效率 + 输入-输出比对**，把"我觉得"换成"数据显示"。

## 二、三层架构

```
┌─ 数据接入层 ──┐   ┌─ 方法论层 ─────────┐   ┌─ 呈现层 ────────┐
│ 知乎开放平台   │ → │ M1~M10 模块        │ → │ 诊断 / 处方 /   │
│ 全量创作抓取   │   │ 定位·选题·算法…    │   │ 依据（可直读）  │
│ 热榜·收藏·关注 │   │ symptom→cause→动作 │   │ 日报 / 台账     │
└───────────────┘   └────────────────────┘   └────────────────┘
```

- **数据接入层**（`scripts/`）：抓取 → 结构化 → 统计。纯本地，JSON 落盘，可复现
- **方法论层**（`M1~M10/`）：十模块，每模块 README 含「待填方法清单」
- **呈现层**：诊断结论 + 具体动作 + 依据链接（指向具体方法论 md，可直读全文）

> 本仓库是方法论层 + 数据接入参考实现；本地 vault 为工作真源，本仓库为**脱敏发布子集**，二者分离不互相污染。

## 三、快速开始

### 3.1 现场演示（两条入口 · 离线零依赖）

```bash
python demo/server.py --no-browser      # 起本地页面（默认 http://127.0.0.1:8699）
# Windows 也可双击 demo/run_demo.bat
```

- **入口① 账号诊断**：选演示账号类型 → 七节诊断报告 + 处方单。处方按状态分四组呈现：**本期行动清单（命中）/ 观察项 / 待补样本 / 已排除**，每条含 异常信号 → M1~M10 模块 → 具体动作 → 依据 md → 失效条件。规则族 15 条全跑（不漏检），进行动清单的只有真正命中的 → **换一个账号，清单跟着变**。
- **入口② 贴入式内容分析**：**不需要任何账号授权**，贴一段文本即可出 M4 爆款要素体检 + 结构诊断 + M10 合规风险自查 + 校验规则插槽

> 现场若没有 Python / 断网：直接双击预渲染单文件 HTML（见 `scripts/prerender_demo.py` 生成），内容与在线演示同源。

### 3.2 命令行链路

```bash
# 1. 配置凭证（Access Secret 从 https://developer.zhihu.com/profile 生成）
zhihu-cli auth set --secret-stdin

# 2. 拉取全量创作（自动翻页 → jsonl + 统计摘要）
python scripts/zhihu_fetch.py --out data/contents.jsonl

# 3. 诊断（年度节奏 / 爆发期切片 / 类型效率 / 题材效率 / 篇幅同期对照 / CTA 对照）
python scripts/zhihu_diagnose.py --in data/contents.jsonl --out out/

# 4. 处方（异常信号 → 模块 → 动作 → 依据 → 失效条件；按 行动/观察/待补/已排除 分组）
python scripts/prescribe.py --in data/contents.jsonl --out out/ --json out/prescribe.json

# 5. 贴入式内容分析（无需账号；规则从外部 JSON 读，注入 --rules 即换规则库）
python scripts/content_analyze.py --file 草稿.md
```

### 3.3 一键验收

```bash
python scripts/e2e_test.py                     # 23 项
python scripts/e2e_test.py --real data/contents.jsonl    # 带上真实样本回归
python -m unittest discover -s tests -t .      # 单元/边界（54 项）
```

> 验收口径：e2e 的「真实样本回归」一项在没给 `--real` 时会**跳过但仍计入通过**——看数时注意区分「跑过」与「跳过」。


## 四、诊断输出什么

| 分析 | 回答什么 | 方法 |
|---|---|---|
| 年度节奏 | 我是越来越好还是越来越差 | 按年聚合均赞 / 零赞率 |
| 爆发期切片 | 最近 7/30/60 天真实水平 | 滑动窗口，**避开历史爆款污染** |
| 类型效率 | 回答/文章/想法/提问哪个性价比高 | 分组聚合 |
| 题材效率 | 我把产能压在了对的地方吗 | 正则分组 + 均赞对比 |
| 篇幅对照 | 写长还是写短 | **同期对照**（同期长文组 vs 短文组） |
| CTA 对照 | 我的引导话术有没有反作用 | 同期对照（含 vs 不含） |
| 输入-输出比对 | 为什么我只会写这一类 | 收藏/关注主题分布 vs 输出主题分布 |

**核心纪律**：所有对比必须**同期对照**。直接拿全量比会被历史爆款污染，得出反向的错误结论。

## 五、已知平台机制（已写进诊断逻辑，L0 核实）

- 创作等级：Lv7 = 6万~11.5万分，Lv8 = 11.5万~22.5万
- Lv7 权益：自定义推广 / 圆桌主持人 / 关注者在看
- 付费咨询开通：Lv4 + 实名 + 注册满 3 个月 + 近 90 天活跃 45 天 + 盐值 >500 + 专项考试
- ⚠️ **扣分红线**：连续 3 天发布内容 <100 字或含大量导流信息 → 创作行为分归零重计
- ⚠️ AI 生成内容未标注被举报 → 内容质量分单次最高扣 200

## 八、红线

- 只处理**本人授权**的账号数据，不爬他人、不采好友
- 数据纯本地，不上传、不回显他人信息
- 结论必须附**失效条件**，禁止只有断言
- 平台规则变动须重新核实，不沿用旧笔记
